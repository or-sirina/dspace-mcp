# dspace-mcp

> **[English](README.md)** · Русский

MCP-сервер, предоставляющий ИИ-агенту стабильный типизированный интерфейс
для управления институциональными репозиториями DSpace: сборка пакетов
Simple Archive Format (SAF), выполнение команд `bin/dspace`, пакетное
редактирование метаданных, нормализация авторов/COAR/ORCID, наукометрический
сбор публикаций по аффилиации, загрузка PDF открытого доступа (включая
Unpaywall), LLM-обогащение метаданных, а также администрирование и
диагностика репозитория.

Инструмент вырос из разовых скриптов администрирования open.mgimo.ru
(DSpace 6.3), но не привязан к этой организации: каждое значение, зависящее
от учреждения (хост/учётные данные/handle-префикс/строка аффилиации/название
журнала/карта типов), задаётся в конфигурации или аргументом инструмента
(см. «Подключение другой организации» ниже), а слой учёта версий охватывает
DSpace 5.x–8.x.

## Как это работает

Два контура исполнения:

- **Локально, без сервера**: сборка пакетов SAF, конвертация выгрузок OJS XML,
  запросы к наукометрическим API, загрузка PDF открытого доступа,
  LLM-обогащение, дедупликация/пакетирование. Всё выполняется на машине, где
  запущен MCP-сервер.
- **Удалённо, по SSH**: всё, что касается собственно установки DSpace
  (командная строка `bin/dspace`, PostgreSQL, файловое хранилище),
  выполняется на настроенном хосте через `ssh`/`scp`. Для классических
  инстансов DSpace (<7) это обязательно, так как REST API там часто
  сломан/отключён, а `import` должен выполняться от root. Позже можно добавить
  REST-путь для инстансов, где REST DSpace 7/8 заведомо работает, но сейчас
  каждый инструмент работает с CLI/БД DSpace, а не с REST.

## Защищённые операции записи

- Чтение, локальные сборки и вызовы внешних API выполняются всегда.
- Изменяющие операции DSpace (`saf_import`, `metadata_import`, `item_update_*`,
  `filter_media`, `cleanup`) по умолчанию выполняются с **confirm=False**: они
  сообщают точные команды, которые выполнили бы, и предсказанный эффект, но
  ничего не исполняют. Передайте `confirm=True`, чтобы выполнить их на самом
  деле.
- Прямые изменения базы данных/хранилища (`collection_create`,
  `set_collection_logo`, `set_intranet_access`, а также инструменты
  нормализации при записи) дополнительно требуют `allow_db_write=True`, что
  запускает автоматический `db_backup()` до любых изменений.

Это проверено: при `confirm=False` инструменты `saf_import`/`metadata_import`/
`filter_media` возвращаются мгновенно с нулевым сетевым вводом-выводом
(проверено против недостижимого хоста) и сообщают точные удалённые команды,
которые бы выполнили.

## Установка

Требуется Python >= 3.10 и [`uv`](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/or-sirina/dspace-mcp.git
cd dspace-mcp
uv venv .venv
uv pip install -e . --python .venv/bin/python
```

Зарегистрируйте сервер в MCP-клиенте (например, в `.claude.json`, по аналогии
с тем, как настроены другие stdio-серверы):

```json
{
  "mcpServers": {
    "dspace-mcp": {
      "type": "stdio",
      "command": "uv",
      "args": ["--directory", "/path/to/dspace-mcp", "run", "dspace-mcp"]
    }
  }
}
```

Готовые сниппеты регистрации для Claude Desktop / Claude Code, Cursor, VS Code
(Copilot, Cline, Roo Code), Continue.dev, opencode, DeepSeek Harness и любого
универсального stdio-клиента — в [docs/INSTALLATION.md](docs/INSTALLATION.md).

## Настройка

Скопируйте `config.example.toml` в `~/.config/dspace-mcp/config.toml` (или
укажите другой путь через `DSPACE_MCP_CONFIG`) и заполните один блок
`[profile.<имя>]` на каждый экземпляр DSpace. **Никогда не записывайте секреты
прямо в файл** — любое строковое значение вида `"env:ИМЯ_ПЕРЕМЕННОЙ"`
подставляется из переменных окружения в момент загрузки:

```toml
[profile.mgimo]
dspace_version = "6.3"
admin_eperson = "admin@example.org"
handle_prefix = "123456789"

[profile.mgimo.ssh]
host = "203.0.113.10"
user = "deploy"
identity_file = "~/.ssh/id_dspace"   # предпочтителен ключ, а не пароль

[profile.mgimo.db]
password = "env:DSPACE_DB_PASSWORD"

[profile.mgimo.api]
unpaywall_email = "you@example.org"
llm_api_key = "env:DEEPSEEK_API_KEY"
```

Большинство инструментов принимают необязательный аргумент `profile`,
выбирающий блок `[profile.*]`; если настроен только один, он выбирается
автоматически, иначе задайте `DSPACE_MCP_PROFILE` или передавайте `profile`
явно при каждом вызове.

**Замечания по безопасности, перенесённые из заменяемых скриптов:**
- Предпочитайте `ssh.identity_file` вместо `ssh.password`/`sudo_password`.
  Парольная аутентификация сохранена для совместимости со старыми
  установками, но пароль ненадолго виден в `ps` на удалённом хосте при
  `sudo -S`.
- Настройте NOPASSWD sudo для команд `dspace` CLI/chown, которые нужны
  серверу, если хотите полностью избежать передачи пароля — `sudo_run()`
  всегда сначала пробует `sudo -n` и лишь затем передаёт пароль, если он
  настроен.
- Если вы переносите скрипты, в которых API-ключ или пароль БД был зашит в
  исходный код, смените эти учётные данные — после попадания в открытый вид
  они уже скомпрометированы.

## Подключение другой организации

Сервер мультиинституциональный по замыслу — МГИМО это просто первая площадка,
для которой он был собран, а не зашитая цель. В логике инструментов нет ни
одной ссылки на МГИМО, конкретный handle-префикс или хост; каждое значение,
зависящее от учреждения (SSH-хост/учётные данные, учётные данные БД,
handle-префикс, раскладка хранилища, карта типов COAR, IP-диапазоны,
LLM-провайдер/ключ, строка аффилиации), — это поле конфигурации или аргумент
инструмента.

Чтобы подключить вторую (или двадцатую) организацию:

1. Добавьте новый блок `[profile.<короткое-имя>]` в `config.toml` — полный
   шаблон см. в `[profile.example_university]` в `config.example.toml`
   (DSpace 7, `dspace-angular`, OpenAI-совместимый LLM вместо DeepSeek — всё
   отличается от примера МГИМО рядом).
2. Сначала выполните `dspace_ping(profile="<короткое-имя>")`, чтобы проверить
   доступность SSH/БД/Tomcat/Solr, прежде чем пробовать что-либо ещё.
3. Выполните `list_communities`/`list_collections`/`resolve_field_id`, чтобы
   убедиться, что готовый SQL в `dspace/cli.py`/`dspace/admin.py` (написанный
   под классическую схему с uuid-ключами) совпадает с этим инстансом; если
   нет — используйте `raw_sql`, чтобы найти правильные имена таблиц/колонок,
   а не предполагать схему МГИМО.
4. Для `harvest_by_affiliation` передайте строку аффилиации этой организации
   (например, `"University of Example"`) и `filename_prefix` (например,
   `"uex"`), чтобы имена скачанных PDF не пересекались с другой организацией,
   если обе запускаются в общем рабочем каталоге.
5. Для `saf_from_ojs_xml` передайте собственные `journal_name_en`/
   `journal_name_ru`/ISSN — в конвертере OJS ничего не предполагается про
   конкретный журнал или пару языков.
6. Для `assign_coar_types` карта `type_map` по умолчанию отражает исторические
   значения `dc.type` одной организации (смесь английских и русских строк —
   так в записях МГИМО); передайте свою `type_map`, отражающую реальные
   значения `dc.type` этого инстанса; сначала `list_communities`/`raw_sql`
   покажут текущее распределение.

Больше ничего менять не нужно — одни и те же 33 инструмента, то же поведение
защищённой записи и тот же слой учёта версий применяются к каждому профилю.

## Справочник инструментов

**Интроспекция** — `dspace_ping`, `list_communities`, `list_collections`,
`resolve_field_id`, `raw_sql`, `server_health`.

**Сборка SAF (локально)** — `saf_build_from_csv`, `saf_generate_manifest`,
`saf_validate`, `saf_repair`, `saf_from_ojs_xml`.

**Метаданные / импорт** — `metadata_export`, `metadata_import`, `saf_import`,
`item_update_add_bitstreams`, `item_update_delete_bitstreams`, `filter_media`,
`index_discovery`, `cleanup`.

**Нормализация** — `normalize_authors`, `assign_coar_types`, `harvest_orcid`,
`apply_orcid_matches`.

**Администрирование** — `db_backup`, `collection_create`,
`set_collection_logo`, `set_intranet_access`.

**Наукометрия / открытый доступ** — `harvest_by_affiliation` (OpenAlex,
CrossRef, CORE, Semantic Scholar), `deduplicate`, `batch_missing`,
`download_oa_pdfs` (через Unpaywall), `extract_pdf_text`, `enrich_metadata_llm`.

У каждого инструмента есть docstring, видимый вызывающему агенту, с описанием
точного поведения, аргументов и ограничений — читайте их в первую очередь;
этот список лишь оглавление.

## Юзкейсы

**Наполнение целого направления по аффилиации (наукометрический конвейер).**
`harvest_by_affiliation` → `deduplicate` (по существующим выгрузкам метаданных)
→ `download_oa_pdfs` (Unpaywall) → `enrich_metadata_llm` → `saf_build_from_csv`
→ `saf_import`. Название организации превращается в пакет проверенных,
дедуплицированных записей с PDF, готовых к импорту.

**Импорт выпуска журнала из OJS/PKP.** `saf_from_ojs_xml` преобразует выгрузку
«Articles and Issues XML» в CSV + извлечённые PDF; `saf_build_from_csv`
собирает SAF; `saf_import` загружает. Двуязычные метаданные и
транслитерированные имена файлов обрабатываются автоматически.

**Пакетная чистка метаданных.** `metadata_export` коллекции в CSV, правка в
табличном редакторе, затем `metadata_import` обратно. Импорт по умолчанию —
«сухой прогон» (`confirm=False`): можно увидеть точную команду и эффект до
выполнения.

**Нормализация авторов / типов / ORCID.** `normalize_authors` приводит к
каноническому виду варианты с ё/е, регистром и пунктуацией; `assign_coar_types`
сопоставляет `dc.type` с двуязычными значениями + URI COAR; `harvest_orcid` +
`apply_orcid_matches` связывают авторов с ORCID через CrossRef.

**Создание и оформление коллекции.** `collection_create` (сначала
structure-builder, затем SQL-фолбэк) → `set_collection_logo` →
`set_intranet_access` для коллекций, ограниченных по IP.

**Диагностика неисправного репозитория.** `dspace_ping` / `server_health`
локализуют сбои SSH/CLI/PostgreSQL/Tomcat/Solr; `db_backup`, `index_discovery`,
`filter_media` и `cleanup` закрывают рутинное обслуживание.

**Добавление или удаление файлов у существующих записей.**
`item_update_add_bitstreams` / `item_update_delete_bitstreams` меняют
битстримы без изменения метаданных (после удаления — `cleanup`).

## Покрытие версий

`src/dspace_mcp/versions/base.py` описывает различия DSpace 5.x–8.x: нужен ли
root для `import`, насколько пригоден REST, как создаются коллекции/логотипы,
и известные отличия CLI по версиям (всё взято из документации LYRASIS DSpace и
сверено с практической эксплуатацией инстанса 6.3). `collection_create`
сначала пробует `structure-builder` (есть с 5.x/6.x) и лишь затем откатывается
на прямой SQL; если готовый SQL-запрос в `list_communities`/`list_collections`
не совпадает со схемой вашего инстанса, используйте `raw_sql` для
интроспекции и сообщите/исправьте расхождение.

## Известные пробелы / планы

- Пока нет REST-бэкенда — всё идёт через SSH + `dspace` CLI + Postgres.
  REST-адаптер за теми же сигнатурами инструментов — естественный следующий
  этап для инстансов DSpace 7/8, где REST доступен и предпочтительнее SSH.
- SQL в `dspace/cli.py` и `dspace/admin.py` нацелен на классическую схему с
  uuid-ключами (проверено вручную на DSpace 6.3); имена таблиц/колонок не
  перепроверялись независимо на живом инстансе 7/8. `raw_sql` — запасной
  выход, когда готовый запрос не совпадает.
- Ключевые наукометрические источники (Scopus, Web of Science, Dimensions) не
  подключены — `scholar/harvest.py` структурирован так, что добавление
  одного — это новая функция `fetch_<источник>` плюс ветка в
  `harvest_by_affiliation`.
- `collection_create` передаёт в `structure-builder` голый элемент
  `<collection>`; проверяйте итоговое размещение/handle, прежде чем
  полагаться на это в массовых операциях, поскольку документированный формат
  вкладывает коллекции в блок `<community>` при объявлении целых поддеревьев.

## Проведённая проверка

- `saf_build_from_csv` на образце CSV → корректные `dublin_core.xml`,
  `metadata_local.xml`, `contents`, `collections`, скопированные битстримы;
  `saf_validate` не находит проблем; `saf_repair` чинит намеренно испорченный
  `contents`.
- `saf_from_ojs_xml` на синтетической выгрузке OJS → корректное двуязычное
  извлечение названий/авторов/аннотаций, очистка HTML, построение ссылок,
  транслитерированное имя файла и base64-извлечение PDF (проверено побайтово).
- `saf_import`/`metadata_import`/`filter_media` с `confirm=False` возвращаются
  за <2 мс против недостижимого хоста (192.0.2.1, RFC 5737 TEST-NET) с
  корректным предпросмотром команд — доказывает нулевой сетевой ввод-вывод до
  подтверждения.
- `dedup`/`batch_missing` корректно отбрасывают дубли внутри пакета и уже
  имеющиеся в корпусе записи и разбивают CSV на части.
- `harvest_by_affiliation` (OpenAlex) выполнен как **живой** вызов через
  реальный путь MCP `call_tool` (а не только через Python-функцию) и вернул
  реальные публикации с аффилиацией МГИМО с корректно сопоставленными полями,
  включая подлинный URL открытого доступа.
- Установленная консольная точка входа (`dspace-mcp`) чисто стартует по
  транспорту stdio без traceback.
- Не проверялось в этот раз (нет доступного DSpace-хоста из среды сборки):
  `dspace_ping`/`saf_import(confirm=True)`/`collection_create` против живого
  инстанса. Сначала выполните `dspace_ping` на реальном профиле, прежде чем
  доверять SSH-зависимым инструментам.
- Автоматизированный набор `pytest` (`tests/`) покрывает локальные пути —
  сборку/валидацию/починку SAF, конвертацию OJS, хелперы
  дедупликации/нормализации, механизмы защищённой записи и разрешение версий
  (Python 3.10–3.13).

## Разработка

```bash
uv pip install -e ".[dev]" --python .venv/bin/python
.venv/bin/python -m pytest
```

Набор тестов локальный и не требует DSpace-хоста. SSH/CLI/Postgres-инструменты
проверяются вручную на живом профиле (сначала `dspace_ping`). См.
[CONTRIBUTING.md](CONTRIBUTING.md) и [SECURITY.md](SECURITY.md).
